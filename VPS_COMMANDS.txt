 labustagialla.it — deploy cheat-sheet
 Portfolio takes /, writerblog moves to /blog/. Copy-paste ONE STEP at a time
 and read the CHECK line before moving on.

FINAL TOPOLOGY

  /                       portfolio      127.0.0.1:8010   (HiImIon)
  /static/ /panel/        portfolio      127.0.0.1:8010
  /django-admin/          portfolio      127.0.0.1:8010   (localhost only)
  /robots.txt             portfolio      — carries Disallow: /blog/
  /blog/                  writerblog     127.0.0.1:8000
  /blog/static/           writerblog     alias /root/writerblog/staticfiles/
  /blog/media/            writerblog     PROXIED, never aliased (gated uploads)
  /blog/panel/            writerblog     127.0.0.1:8000
  /ezbk/                  ezBookkeeping  127.0.0.1:8080   (unchanged)
  /cff/…                  festival       fest_web/fest_api (unchanged)

Confirmed on this box already:
  - running as root, HOME=/root, so the app lands at /root/HiImIon
  - port 8010 is free; 3000/3001/8000/8080/4000 are taken
  - the server block lives in /etc/nginx/sites-available/writerblog
    (symlinked from sites-enabled), cert /etc/letsencrypt/live/labustagialla.it/
  - rate-limit zones wb_auth and wb_global already exist and are reused

ORDER MATTERS. STEP 2 and 3 are invisible to visitors — the portfolio runs on
localhost with nothing routed to it. STEP 4 must finish before STEP 5, or
/blog/ will proxy to an app that still only answers on /.


───────────────────────────────────────────────────────────────────────────
 STEP 0 — BACKUPS. DO NOT SKIP.
───────────────────────────────────────────────────────────────────────────

cp /root/writerblog/db.sqlite3 "/root/writerblog-db.bak-$(date +%F-%H%M).sqlite3"
sudo cp /etc/nginx/sites-available/writerblog "/root/writerblog-nginx.bak-$(date +%F-%H%M)"
ls -la /root/writerblog-db.bak-* /root/writerblog-nginx.bak-*

CHECK: two files listed. The .sqlite3 is the writer's actual content and the
nginx file is your one-command undo for STEP 5.


───────────────────────────────────────────────────────────────────────────
 STEP 1 — PRE-FLIGHT (already done; re-run only if the box changed)
───────────────────────────────────────────────────────────────────────────

Use grep -R (capital), never -r: sites-enabled is symlinks and lowercase -r
skips them silently. Do not put "!!" in a double-quoted echo — bash history
expansion mangles the line.

echo "=== is 8010 free? ==="; ss -tlnp | grep -E ':(8010)\b' || echo "8010 free"
echo "=== nginx map ==="; sudo nginx -T 2>/dev/null | grep -E "^# configuration file|server_name |listen " | sed 's/^[[:space:]]*//'
echo "=== locations ==="; sudo nginx -T 2>/dev/null | grep -E "^[[:space:]]*(location|proxy_pass|alias) " | sed 's/^[[:space:]]*//'


───────────────────────────────────────────────────────────────────────────
 STEP 2 — PORTFOLIO: CLONE AND SET UP  (invisible to visitors)
───────────────────────────────────────────────────────────────────────────

cd "$HOME"
git clone https://github.com/Rehd96/HiImIon.git
cd "$HOME/HiImIon"

python3 -m venv venv
./venv/bin/pip install -q --upgrade pip
./venv/bin/pip install -q -r requirements.txt
./venv/bin/python -c "import django; print('django', django.get_version())"

Write .env with a REAL generated secret key:

cd "$HOME/HiImIon"
SECRET="$(./venv/bin/python -c 'from django.core.management.utils import get_random_secret_key as k; print(k())')"
cat > .env <<EOF
DJANGO_SECRET_KEY=$SECRET
DJANGO_DEBUG=false
DJANGO_ALLOWED_HOSTS=labustagialla.it,www.labustagialla.it,127.0.0.1
DJANGO_CSRF_TRUSTED_ORIGINS=https://labustagialla.it,https://www.labustagialla.it
DJANGO_SSL_REDIRECT=false
DJANGO_HSTS_SECONDS=0
PAGEVIEW_RETENTION_DAYS=400
EOF
chmod 600 .env

Migrate, collect static, create your panel login:

cd "$HOME/HiImIon"
set -a; . ./.env; set +a
./venv/bin/python manage.py migrate
./venv/bin/python manage.py collectstatic --noinput
./venv/bin/python manage.py createsuperuser

CHECK:
  - "django 5.1.5" printed
  - createsuperuser: STRONG password. This is your /panel/ login, exposed to
    the internet, rate-limited to a few tries a minute — which is not a
    substitute for a good password.


───────────────────────────────────────────────────────────────────────────
 STEP 3 — PORTFOLIO: SYSTEMD  (still invisible to visitors)
───────────────────────────────────────────────────────────────────────────

Generates the unit from your real user and paths. Do NOT install
deploy/hiimion.service directly — it assumes the laptop layout and its
ProtectHome would block SQLite writes under /root.

cd "$HOME/HiImIon"
APP="$HOME/HiImIon"; RUNAS="$(whoami)"
sudo tee /etc/systemd/system/hiimion.service > /dev/null <<EOF
[Unit]
Description=labustagialla.it portfolio (Django + Gunicorn)
After=network.target

[Service]
Type=simple
User=$RUNAS
WorkingDirectory=$APP
EnvironmentFile=$APP/.env
ExecStart=$APP/venv/bin/gunicorn hiimion.wsgi:application --bind 127.0.0.1:8010 --workers 3 --timeout 30 --access-logfile - --error-logfile -
ExecReload=/bin/kill -s HUP \$MAINPID
Restart=always
RestartSec=5

NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ReadWritePaths=$APP
ProtectKernelTunables=true
RestrictSUIDSGID=true

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now hiimion
sleep 2
systemctl status hiimion --no-pager | head -12

Smoke-test on localhost BEFORE nginx knows it exists:

curl -sI http://127.0.0.1:8010/             | head -1
curl -sI http://127.0.0.1:8010/panel/login/ | head -1
curl -s   http://127.0.0.1:8010/robots.txt  | grep blog
curl -s   http://127.0.0.1:8010/ | grep -o "<h3 class=\"card-title\">[^<]*" | sed 's/.*>//'

CHECK:
  - status "active (running)"
  - both curls "HTTP/1.1 200 OK"
  - robots grep prints "Disallow: /blog/"
  - the last command lists SIX project names

IF IT FAILED:
  sudo journalctl -u hiimion -n 40 --no-pager
  Usual causes: missing .env, 8010 taken, venv path wrong.
  STOP — do not continue to STEP 5.


───────────────────────────────────────────────────────────────────────────
 STEP 4 — WRITERBLOG: MOVE TO /blog/
───────────────────────────────────────────────────────────────────────────

4a. Pull the new code:

cd /root/writerblog
source venv/bin/activate
git pull

4b. MIGRATION CONFLICT — diagnose before doing anything.

If migrate reports "multiple leaf nodes in the migration graph", the VPS has
migration files that were generated here and never committed, so the server's
history diverged from the repo. DO NOT run "makemigrations --merge" on the
VPS: it writes yet another file that exists only here and the next git pull
will refuse to overwrite it. Collect this and send it over:

cd /root/writerblog && source venv/bin/activate
echo "=== migration files ==="; ls blog/migrations/
echo "=== tracked by git? ==="; git status --short blog/migrations/
echo "=== applied ==="; python manage.py showmigrations blog
echo "=== django_migrations rows ==="; python -c "
import sqlite3; c=sqlite3.connect('db.sqlite3')
for r in c.execute(\"select id,name,applied from django_migrations where app='blog' order by id\"): print(r)"
echo "=== blog tables ==="; python -c "
import sqlite3; c=sqlite3.connect('db.sqlite3')
print([r[0] for r in c.execute(\"select name from sqlite_master where type='table' and name like 'blog_%'\")])"

Context for reading it: in the repo the history is LINEAR —
0001 → 0002 → 0003_access_log (creates BOTH AccessLog and ActivityLog) →
0004_membership. Any 0003_activitylog or 0004_merge_* file is VPS-only.

  - blog_activitylog exists AND the merge is applied → server is ahead of git.
    Fix: bring the two VPS files into the repo, generate the merge on the
    laptop, commit, pull. History reconverges, nothing re-runs.
  - the files exist but were never applied → delete the untracked ones and let
    the repo's linear history apply cleanly.
  - 0003_access_log applied but blog_activitylog missing → faked/partial state,
    needs --fake on specific rows. Do not improvise this one.

4c. Once the graph is resolved:

cd /root/writerblog && source venv/bin/activate
python manage.py migrate --noinput
python manage.py collectstatic --noinput
systemctl restart writerblog
sleep 2

curl -sI http://127.0.0.1:8000/blog/ | head -1
curl -sI http://127.0.0.1:8000/      | head -1

CHECK:
  - /blog/ → 200
  - /      → 404   ← this is the important one. It proves the new URL conf is
                     live and writerblog has stopped claiming the root. If it
                     returns 200, the old code is still running: STOP, or
                     STEP 5 will leave the blog fighting the portfolio for /.


───────────────────────────────────────────────────────────────────────────
 STEP 5 — THE NGINX SWAP  (this is the step that goes public)
───────────────────────────────────────────────────────────────────────────

cd "$HOME/HiImIon" && git pull
sudo cp deploy/nginx-labustagialla-merged.conf /etc/nginx/sites-available/writerblog
sudo nginx -t

CHECK: "syntax is ok" and "test is successful". If not, DO NOT reload — fix it
or restore from STEP 0. Only then:

sudo systemctl reload nginx

What that file changes, all on the writerblog side:
  /static/       → /blog/static/
  /panel/login/  → /blog/panel/login/
  /django-admin/ → /blog/django-admin/
  location /     → location /blog/
  /media/        → DELETED, not renamed. gate_views.protected_media puts
                   uploads behind a membership check, so Django must serve
                   them; an nginx alias hands them to anyone with the URL.
  + X-Forwarded-Proto on every blog block — writerblog sets
    SECURE_PROXY_SSL_HEADER but nginx never sent the header, so Django saw
    every HTTPS request as plain HTTP.
/ezbk/, the festival include and all TLS directives are unchanged.

 STEP 6 — VERIFY ALL FOUR APPS
───────────────────────────────────────────────────────────────────────────

for p in / /about/ /projects/rentwatch/ /projects/castelfidardo-festival/ \
         /panel/login/ /robots.txt /static/css/site.css \
         /blog/ /blog/panel/login/ /cff/ /ezbk/; do
  printf '%-42s %s\n' "$p" "$(curl -so /dev/null -w '%{http_code}' "https://labustagialla.it$p")"
done

CHECK:
  / /about/ /projects/* /panel/login/ /robots.txt /static/css/site.css → 200
  /blog/ /blog/panel/login/                                            → 200
  /cff/ /ezbk/                                                         → 200 or 301/302

  404 on /static/css/site.css  → portfolio alias path wrong (STEP 5 file)
  404 on /blog/                → writerblog still on old code (back to STEP 4c)
  502 on /                     → gunicorn not running (back to STEP 3)

Then in a browser:
  https://labustagialla.it/            the portfolio, six project cards
  https://labustagialla.it/blog/       the writer's site, CSS intact
  https://labustagialla.it/panel/      log in with the STEP 2 superuser

Confirm the blog's CSS actually loads — a bare unstyled page means
/blog/static/ is misrouted even though the status code is 200.

 ROLLBACK
═══════════════════════════════════════════════════════════════════════════

nginx broken, or you want the blog back at / :
    sudo cp /root/writerblog-nginx.bak-<timestamp> /etc/nginx/sites-available/writerblog
    sudo nginx -t && sudo systemctl reload nginx
    (that backup predates the swap, so it restores blog-at-root exactly)

Portfolio code bad:
    cd "$HOME/HiImIon" && git log --oneline -5
    git checkout <previous-sha> && sudo systemctl restart hiimion
    (its database holds only page views — rolling back is always safe)

Writerblog database damaged by a migration:
    systemctl stop writerblog
    cp /root/writerblog-db.bak-<timestamp>.sqlite3 /root/writerblog/db.sqlite3
    systemctl start writerblog

Take the portfolio down entirely:
    sudo systemctl stop hiimion && sudo systemctl disable hiimion
    (then roll nginx back, or / will 502)
